# AI team configurator: costs, saved configurations, PDF plan and consultations

Extends "Build your AI team" (`/bg/instrumenti/ai-ekip` ↔ `/en/tools/ai-team`, rules in
[TOOLS_PLATFORM.md](TOOLS_PLATFORM.md#ai-team-model-libai-teamts)) with a transparent cost estimate,
a server-side plan (security, data flows), a PDF, private saved links and an optional consultation.
Nothing here deploys, configures or runs an agent; every page and the PDF say so.

| Action | What leaves the browser | Stored | Endpoint |
| --- | --- | --- | --- |
| Build the team, see the result | nothing | nothing | — |
| Costs, security, data flows (result page) | enumerated configuration + optional rate overrides | nothing | `POST /api/public/team/estimate` |
| Download the PDF plan | the above + optional company name for the cover | nothing | `POST /api/public/team/report` |
| Save the configuration (after ticking the storage consent) | the above (no company) + `storage_consent: true` | configuration row, 90 days | `POST /api/public/team/configurations` |
| Open a saved link | the secret token (request body) | — | `POST /api/public/team/configurations/lookup` |
| Request a consultation | the above + name, work e-mail, company, role, message, consents | lead + linked configuration | `POST /api/public/team/submissions` |

## Design

* **One model, two implementations, tested together.** The rules live in `apps/web/src/lib/ai-team.ts`
  and are ported to `apps/api/app/team/model.py`. 64 golden vectors (`apps/api/tests/fixtures/team_vectors.json`
  = `apps/web/src/lib/team.vectors.json`, generated by `apps/api/scripts/gen_team_vectors.py`) are
  checked by pytest and vitest; `scripts/test.ps1` fails if the copies differ. `model_version`
  (`2026-10.1`) must match or the API answers 422 `team_model`.
* **The server is the only cost calculator.** `app/team/costs.py` + a versioned assumptions document;
  the UI renders what `/estimate` returns, so the page, the PDF and a stored consultation always agree.
* **The server re-derives everything** (team, approvals, complexity, plan, costs) from the enumerated
  configuration; browser-computed results are never accepted. A checkpoint below a rule minimum is
  raised, unknown integrations dropped, settings for agents outside the team discarded.
* **One text source.** The PDF uses `app/team/texts.json`, a snapshot of the web content
  (`src/lib/team-texts.ts`, checked by `team-texts.test.ts`; regenerate with `UPDATE_TEAM_TEXTS=1`,
  see that file). Only a few PDF labels live in `app/team/report.py`.

## Cost model (`app/team/costs.py`, assumptions `app/team/pricing/2026-10.1.json`)

Currency EUR (the product's convention), amounts rounded to EUR 10. Every triple in the assumptions
is `[conservative, expected, higher]`; *conservative* = lower usage and a lean scope.

**One-time (days × day rate)** = discovery + Σ agent build days by agent complexity + Σ integration
days by system complexity (`integration_complexity`, e.g. ERP/accounting/HR = high, CRM/helpdesk =
medium, e-mail/calendar/chat = low) + approval set-up × agents approved before acting + environment
set-up (managed / your cloud / on-premise) + testing (share of build and integration days).

**Monthly**
* *Infrastructure* = base + per-agent amount for the environment (on-premise excludes hardware).
* *Model/API usage* = Σ tasks per agent (`volume_tasks` per band) × tokens per task (`tokens_per_task`
  per agent) × price per 1M tokens × overhead for retries and evaluation. The coordinator runs once per
  task, the approval supervisor once per approval request. Prices are labelled illustrative and must be
  checked against the provider's current price list.
* *Monitoring & maintenance* = studio hours (base + per agent) × day rate / 8 + your team's hours per
  agent × internal hourly rate, by management model (we / shared / your team).
* *Human oversight* (your team's time) = reviews × minutes per review × internal hourly rate; reviews =
  tasks × share by checkpoint (sample review 3/5/10 %, before external actions 40/60/80 %, every action
  100 %). Only task agents count.

**Editable and versioned.** All values are in the JSON document (`version` is recorded with every
estimate, saved configuration and consultation). To change them, copy the file to
`app/team/pricing/<new-version>.json`, edit, and point `TEAM_COST_ASSUMPTIONS_FILE` at it (or replace
the default and bump `version`). Keep old files: the admin PDF of a stored consultation uses the
version it was priced with while that file exists (`assumptions_for_version`), otherwise the current
one. The document is validated at load (`AssumptionsError` → 503 `estimate_unavailable`).
Visitors may override four rates within bounds (`OVERRIDE_BOUNDS`): day rate 200–2500, internal hourly
rate 5–250, price per 1M input tokens 0–100, per 1M output tokens 0–300. Overrides are recorded.

No productivity, savings or ROI figures are produced anywhere.

## API

Error envelope and `Accept-Language: bg|en` as in [API_REFERENCE.md](API_REFERENCE.md#error-envelope).

### Configuration (request field `config`)

```json
{
  "context": {"industry": "ecommerce", "size": "s11_50", "lead_department": "support",
              "challenge": "slow_response", "volume": "v100_1k"},
  "departments": ["support"],
  "chosen": ["customer_support"],
  "agents": {"customer_support": {"volume": "v100_1k", "integrations": ["helpdesk", "knowledge_base", "email"],
                                   "checkpoint": "before_external"}},
  "deployment": "managed_cloud",
  "operations": "shared"
}
```

Enumerations as in `app/team/model.py`. Rules: unknown keys or values → 422; duplicates → 422
`team_duplicates`; no task agent, or a coordinator with fewer than two task agents → 422
`team_selection`. The custom department name is never part of the API.

Common request fields: `schema_version` (`"1"`), `model_version` (`"2026-10.1"`, else 422
`team_model`), `locale` (`bg`|`en`), `config`, optional `overrides`
(`day_rate`, `internal_hourly_rate`, `price_per_million_input`, `price_per_million_output`).

| Endpoint | Request extras | Response | Limits |
| --- | --- | --- | --- |
| `GET /api/public/team/meta` | — | versions, `assumptions` (whole document + `editable` bounds and defaults), `retention_days`, `submission_retention_days`, `email_delivery: false` | — |
| `POST /api/public/team/estimate` | — | `{model_version, summary, security, data_flows, estimate}` (below) | `TEAM_ESTIMATE_RATE_LIMIT` per client |
| `POST /api/public/team/report` | `company?` (≤ 120, no links/HTML), `form_token` | `application/pdf` (`ai-ekip-plan.pdf` / `ai-team-plan.pdf`), `no-store`, `nosniff` | `TEAM_REPORT_RATE_LIMIT`; form token |
| `POST /api/public/team/configurations` → 201 | `form_token`, `storage_consent` (must be `true`; missing or anything else → 422, nothing stored) | `{reference, token, expires_at}` | `TEAM_SAVE_RATE_LIMIT`; form token |
| `POST /api/public/team/configurations/lookup` | `{token}` only | `{reference, created_at, expires_at, schema_version, model_version, assumptions_version, locale, config, overrides}`; 404 `team_configuration_not_found` | `TEAM_LOOKUP_RATE_LIMIT` |
| `POST /api/public/team/submissions` → 201 | `name`, `email`, `company`, `role`, `message?`, `privacy_acknowledged` (must be true), `marketing_consent` (default false), `website` (honeypot), `form_token` | `{reference, message}` | contact-form limit; honeypot; form token; link spam |
| `GET /api/admin/leads/{id}/team-report` (admin) | — | `application/pdf` from the stored configuration; audited `lead.team_report_downloaded`; 404 for other leads | session |

All limits share `TEAM_RATE_WINDOW_SECONDS` and `TEAM_GLOBAL_RATE_LIMIT`. Rate limits are applied
before validation.

`estimate` = `{assumptions_version, currency, rates, overrides, scenarios: {conservative, expected,
higher}, ranges: {one_time: [min, max], monthly: [min, max]}}`; each scenario has `one_time`
(`discovery, agents, integrations, approvals, deployment, testing, total`), `one_time_days`,
`integrations` (per system: complexity, days), `monthly` (`infrastructure, model_usage, monitoring,
oversight, total`), `usage` (tasks, input/output tokens), `oversight` (reviews, hours),
`monitoring_hours` (studio, internal). `summary` is the shape of the parity vectors (selected agents,
effective agent settings, complexity with factors, risks, prerequisites, workflows, rollout, related
services, architecture graph). `security` is a list of keys (texts in the content); `data_flows`
lists reads from shared data and actions in systems, with the approval checkpoint when gated.

`GET /api/admin/leads/{id}` returns `team` (`reference, model_version, assumptions_version, role,
agents, complexity, deployment, operations, currency, one_time_range, monthly_range,
expected_one_time, expected_monthly`) for configurator consultations. Admin retention preview/run
report `team_configurations_due` / `team_configurations_deleted`.

## Privacy and security

* **Data minimisation.** Configurations are enumerated values; no free text except the optional PDF
  company name (not stored) and the consultation fields. Settings for agents outside the team are
  dropped before storage.
* **Saved links.** 32-byte random token (`secrets.token_urlsafe`); only its SHA-256 is stored
  (`token_hash`, unique). The token travels in a POST body, never in an API URL, so request logs never
  contain it (tested). The browser link `?c=<token>` is the only key; there is no listing or search.
  Expired and lead-linked rows cannot be opened.
* **Retention.** Unlinked saved configurations: `TEAM_CONFIGURATION_RETENTION_DAYS` (90). Consultation
  leads (`source = team_configurator`): `TEAM_LEAD_RETENTION_DAYS` (365) or `LEAD_RETENTION_DAYS`,
  whichever is shorter; their configuration row is deleted with the lead (FK `ON DELETE CASCADE`).
  Purged by `python -m app.cli maintenance` and *Admin → Retention*.
* **Consent.** Privacy acknowledgement required (version recorded); marketing consent separate,
  unticked, versioned (`marketing_consent_version`). **Saving** stores only an explicitly consented
  configuration: the save card has an unticked box stating what is kept and for how many days; without
  it the UI shows an error and sends nothing, and the API rejects a request without
  `storage_consent: true` (`Literal[True]`, tested). Downloading and estimating store nothing and need
  no consent.
* **Logs** carry counts, enumerations and references only (agents count, complexity band, locale,
  configuration/lead reference) — never tokens, names, e-mails, companies or messages (tested).
* **No e-mail promises.** `email_delivery` is `false`; the UI says no automatic e-mails are sent.

### Privacy assumptions to confirm

1. The legal basis for a consultation is the visitor's request; the privacy policy should mention the
   configurator and that the configuration is stored with the inquiry.
2. A configuration (industry, size band, departments, agent roles) is not personal data on its own.
3. 90 days for saved links and 365 days for consultations are defaults — align with the documented
   retention schedule.
4. The illustrative model prices in the assumptions are not provider quotes; review them before
   publishing new versions.

## Migration notes

* `apps/api/alembic/versions/20261027_0007_team_configurations.py` (revision `0007`, down `0006`)
  creates `team_configurations` (UUID PK, timestamps, `token_hash` unique nullable, versions, `locale`
  CHECK bg/en, `config` / `overrides` JSONB, `lead_id` FK → `leads.id` ON DELETE CASCADE, indexes on
  `expires_at` and `lead_id`). New table only; no existing row changes. Downgrade drops the table
  (saved links stop working; leads keep their summary in `service_details`).
* Verified by `test_models_match_migrations` (`alembic check`) and the upgrade/downgrade round trip.
* **Applying safely:** take a backup, then `docker compose exec api alembic upgrade head` (or let the
  container do it with `RUN_MIGRATIONS_ON_START=true`). Check with `alembic current` → `0007`. To roll
  back: `alembic downgrade 0006`. **Not applied to production.**
* New optional settings (safe defaults): `TEAM_COST_ASSUMPTIONS_FILE`, `TEAM_ESTIMATE_RATE_LIMIT`,
  `TEAM_REPORT_RATE_LIMIT`, `TEAM_SAVE_RATE_LIMIT`, `TEAM_LOOKUP_RATE_LIMIT`, `TEAM_RATE_WINDOW_SECONDS`,
  `TEAM_GLOBAL_RATE_LIMIT`, `TEAM_CONFIGURATION_RETENTION_DAYS`, `TEAM_LEAD_RETENTION_DAYS`.
