# Решение за пускане по сигурност — 2026-11-17

Решенията важат за състоянието на този клон след сливане; нищо не е разгърнато. Речник: GO / CONDITIONAL_GO / NO_GO.

| Повърхност | Решение | Основание и условия |
| --- | --- | --- |
| Публичният маркетингов сайт (текущ) | **CONDITIONAL_GO** | Вече работи. Следващото Release (зависимости + този клон) е допустимо **при условие** за SEC-02: преди Release собственикът изпълнява `db-role-check` (=0) и проверява `API_DB_USER`/`API_DB_PASSWORD` в `.env`; иначе API не стартира и Release се връща автоматично |
| Клиентски акаунти | **NO_GO** | `main` има 0 задължителни одобрения (SEC-03); e2e за акаунти не върви в GitHub CI; роля на базата, поща (SPF/DKIM/DMARC), срокове и подпис на юрист — непотвърдени |
| Клиентски портал | **NO_GO** | същото; динамична междунаемателна проба не е изпълнена; RLS не е `FORCE` (смекчено само ако API не е собственик) |
| Качване на файлове | **NO_GO** | няма скенер, квоти, проверено копие на тома; вж. [UPLOAD_RELEASE_GATE_REVIEW.md](UPLOAD_RELEASE_GATE_REVIEW.md) |
| Плащания и абонаменти | **NO_GO** | Stripe е проверен само с фалшив шлюз; няма тестов режим, подписан webhook, правна проверка |
| Пълно активиране на платформата | **NO_GO** | сума от горните |
| Внедряване на този PR | – | Промяната на `compose.yml` не стига до сървъра сама; копира се ръчно след потвърждение |

## Блокери, които изискват собственика или други хора
1. **Ruleset (SEC-03):** прилагане на `infra/github/ruleset-main-strict.json` (след като `Deploy config guard` се е изпълнил поне веднъж на `main`); включване на Dependency graph, Dependabot security updates, „Require actions to be pinned“.
2. **Роля на базата (SEC-02):** `db-role-check` и проверка на `.env` преди Release.
3. **Cloudflare (SEC-07):** потвърждение на режим, правила, Access, актуален списък IP.
4. **Копия (SEC-10):** изпълнена проба за възстановяване; сигнал за продължителни 5xx.
5. **Файлове:** скенер и политика на съхранение.
6. **Stripe/поща/срокове:** сметки, ключове в тестов режим, юрист и счетоводител.

## Критерии за приемане — какво е и какво не е изпълнено
- Всяка потвърдена находка, поправима в кода (SEC-01, SEC-02, SEC-09 частично, SEC-10 частично), има поправка и проверка; останалото е документирано като блокирано или прието.
- Нова критична/висока регресия: не е открита; API 1800/1 пропуснат, ruff чисто.
- Производствени данни и пароли: непроменени. Флагове: непроменени. BG/EN сайтът: кодът му не е пипан.
- План за връщане: отмяна на комитите; аварийно `ALLOW_OWNER_DATABASE_ROLE=true`.
- **Не е изпълнено:** строг CSP, споделен лимит на честотата, скенер за файлове, нови противникови тестове, проверка на Cloudflare/сървър — всичко е описано в регистъра.
