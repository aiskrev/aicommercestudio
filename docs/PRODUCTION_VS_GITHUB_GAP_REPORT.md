# Съгласуване на GitHub и производство: фактически опис (2026-11-13)

Сравнение на `origin/main` @ `deb387c` с това, което реално работи на https://ai-commercestudio.com. Всяко твърдение е отбелязано как е установено:

* **[П] Проверено** – прочетено от код, Git, GitHub API/Actions или от самия сайт (само четене, единични заявки).
* **[Л] Проверено в журнал** – част от изхода на сървъра, отпечатан в журнала на GitHub Actions (стъпките `ssh deploy status/migrate/deploy`). Това е реален изход от сървъра, но към момента на пуска, не към днес.
* **[Д] Допускане** – следва от горното, но не е прочетено от сървъра.
* **[Н] Не е проверимо** – няма достъп (виж т. 1).

## 0. Важна поправка на предишни мои твърдения

1. **Конфигуратор, кошница:** одобрен текст за бисквитките/съхранението → в един комит константата `COMMERCIAL_STORAGE_DISCLOSED = True` + обновен регистър → флагове първо на тестов сървър.
2. **Оферти:** решение на собственика и юрист за значението/текста на отговора → `QUOTATION_ACCEPTANCE_WORDING_APPROVED = True` → флаг.
3. **Акаунти:** пощенска кутия и доставчик, SPF/DKIM/DMARC, `EMAIL_DELIVERY_VERIFIED=true`; срокове за запазване от юрист и счетоводител; правните текстове излезли от „в преглед“; потвърдена роля `acs_app_api`; решение за MFA на клиентите; Cloudflare правила за честотата на входа.
4. **Проекти → документи → известия:** след акаунтите, в този ред, всяка стъпка отделно.
5. **Качвания:** Release на `deb387c`, нов `compose.yml` с том, архив и тест за възстановяване на тома, скенер (или записано приемане), политика и преглед → `PROJECT_UPLOAD_REVIEW_APPROVED = True`.
6. **Stripe:** тестови ключове, пълна пясъчна матрица, решения на счетоводител и юрист, отделна промяна на кода за разрешаване на `stripe` в производство.
7. **Advisor Workspace, портал, статистика, автоматично изтриване:** всяко със собствено решение (виж т. 7).

## 11. Готово за пускане без допълнително разработване

1. **Release на `deb387c`** (`build-only` + `deploy`, без миграция: няма нови). Риск: нисък; връщане: `acs-deploy rollback`.
2. **Настройки на GitHub:** Dependency graph, Dependabot security updates, ruleset (`infra/github/ruleset-main.json`) – настройки за минути, без код.
3. **Сливане/преглед на 11-те PR на Dependabot** (по една група, всяка минава през CI); някои са големи версии (`typescript 7`, `jsdom 31`, `reportlab 5`) – не се сливат без преглед.
4. **Проверка `db-role-check` на сървъра** след пуска (1).
5. **Проверка и прилагане на предложенията за Cloudflare** (правило за входа на персонала, Access пред `/admin`) – решение на собственика.

## 13. Какво НЕ е направено в тази сесия

Не е разгъвано нищо, не е включван флаг и не е променяно на сървъра. Исканията „разгърни или активирай всичко, което е зад флаг“ **не са изпълнени** и причините са фактически: (а) няма достъп до сървъра; (б) производственият старт на API **отказва** част от флаговете (Advisor Workspace, Stripe) и всички с отворени гейтове – включването им би счупило API или би заобиколило правни и сигурностни гейтове, което е изрично забранено; (в) Release изисква одобрение на среда `production` от собственика.
